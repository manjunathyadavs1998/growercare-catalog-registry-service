# catalog-registry-service: project guide for Claude

GrowerCare product master (ADR-017: its own repository): products with active ingredients and packs, registrations per country, and batches (GRW-2/3/5). Users search what is registered in their country and check batches; an ERP / regulatory sync writes through idempotent, version-guarded upserts; case-service replicates products and batches it needs (SPEC-CASE-08). Events `catalog.*` via the outbox. Label rows and the label-compliance check (GRW-4) are not in Phase 1.

## Conventions
1. **Users:** any authenticated GrowerCare user may read; the country is limited by `CountryAccess` (SPEC-CAT-01 D4) and answers 404 outside it. Batches are checked, never listed.
2. **Writes:** only service clients in `GC_IMPORT_CLIENTS` (ERP sync), by business key, with a source `version`; a version not newer than the stored one changes nothing and publishes nothing.
3. **IDs** are strings in JSON; product ids come from a sequence (from 100000; dev seed 9001–9004 matches case-service).
4. **Events only through the outbox**, ids and codes only, key = productId.
5. **No ORM:** named SQL via `JdbcClient` (ADR-013), `sql/postgres/catalog.sql`.
6. **Configuration only from environment variables** (SPEC-PLAT-06), documented in `.env.example`; `ConfigurationHygieneTest` guards it.
7. **Spec-driven development:** spec → parameterized test rows named after spec example IDs → code → green. Rows must stay independent (use fresh product codes).
8. **Reporting:** run `mvn -B verify` before claiming success.
9. **Git workflow:** never commit to `main`; branch `<type>/<name>`; PR body with `Spec: docs/specs/...`; squash-merge when CI, policy and Claude review are green.
